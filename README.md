# NOVA — نسخة اختبار متصلة بـSupabase

تطبيق Flutter بالعربية والإنجليزية، بواجهات Android وiOS والويب. **ليس جاهزًا للإطلاق التجاري.** الاسم مؤقت ولم يُفحص توفره القانوني.

## الحالة الحالية

- استُخدم مشروع NOVA الموجود لدى المالك؛ لم يُنشأ مشروع Supabase ثانٍ.
- نجح الوصول إلى خدمة Auth بالمفتاح العام. التسجيل بالبريد مفعّل وConfirm email معطّل بالفعل؛ لم نغيّر CAPTCHA أو حدود الحماية.
- إعداد الاتصال محفوظ محليًا في `config/local.json` ومستبعد من Git. عنوان الاتصال هو عنوان المشروع الأساسي، دون `/rest/v1/`.
- طُبّقت الترحيلات الأربعة وتأكد الإصدار 4 فعليًا. RLS مفعّل على جداول التطبيق، والوسائط خاصة، وصلاحيات الأرصدة والمشتريات للخادم فقط.
- رُفع المصدر إلى https://github.com/mohamedmohsenarabtec-bot/NOVA . بدأ المستودع خاصًا ثم أصبح عامًا بموافقة المالك الصريحة لأن خطته لا تدعم Pages للمستودعات الخاصة. وجود المستودع لا يعني نجاح نشر الموقع.
- التطبيق المنشور فعليًا: **https://mohamedmohsenarabtec-bot.github.io/NOVA/** . نجح workflow النشر، وتحقق HTTP 200 للصفحة وملفات التشغيل ومسار `/NOVA/`.
- نجح الاختبار الحي الكامل: 18 تحققًا، منها دخول من واجهة الموقع في Chrome وإعادة تحميل المحادثة فعلًا مع بقاء الجلسة والرسائل. حُذف فقط حسابا الاختبار المؤقتان بعد الفحص.

## افتح التطبيق محليًا

```powershell
.\scripts\run.ps1
```

أو إذا منعت سياسة Windows تشغيل السكربت:

```powershell
& 'C:\src\flutter\bin\flutter.bat' run -d chrome --web-port 3000 --dart-define-from-file=config/local.json
```

يفتح Chrome متصلًا بمشروع المالك. على جهاز آخر، انسخ `config/local.example.json` إلى `config/local.json` واملأ URL والمفتاح العام والمرجع. لا تضع أي كلمة مرور قاعدة بيانات أو service-role أو رمز GitHub في إعداد Flutter.

## تسجيل الدخول التجريبي دون SMTP

تأكيد البريد في المشروع الحالي معطّل حسب الفحص الحقيقي. عند نجاح إنشاء الحساب تُنشئ Supabase جلسة مباشرة؛ لا يوجد تسجيل محلي وهمي. يجب إدخال بريد صالح وكلمة مرور من 12 حرفًا على الأقل، وتاريخ ميلاد للبالغين والموافقة على الشروط. قواعد العمر والوصول تُفرض على الخادم.

استعادة كلمة المرور بالبريد **غير مفعّلة في هذه المعاينة**. يوضح الزر ذلك ولا يعد بإرسال رسالة. لا تفعّل `AUTH_EMAIL_RECOVERY_ENABLED` إلا بعد إعداد إرسال البريد واختبار روابط العودة. قبل الإطلاق العام أعد تقييم تأكيد البريد وراجع الأمان والمراجعة القانونية.

## الترحيلات والاختبارات

ملفات `supabase/migrations` الأربعة تحفظ الجداول والسياسات والمطابقة والدردشة وحدود الإساءة وفحص الجاهزية. لا تستخدم db reset على مشروع المالك. يجب فحص المخطط أولًا بواسطة `supabase/inspect_remote.sql` ثم تطبيق الملفات الناقصة فقط، والتحقق بواسطة `supabase/verify_remote.sql`. التفاصيل في [دليل الإعداد والنشر](docs/deployment.md).

```text
dart format --output=none --set-exit-if-changed .
flutter analyze
flutter test
flutter build web --release --base-href=/NOVA/ --dart-define-from-file=config/local.json
flutter build apk --debug --dart-define-from-file=config/local.json
```

الفحص السابق قبل التعديلات: 15 اختبارًا ناجحًا. الاختبارات المحدثة: 21 اختبارًا. نجحت أيضًا اختبارات pgTAP الـ31 على Supabase معزول داخل GitHub Actions. نتائج التنفيذ الفعلية والبناء والاختبارات الحية موجودة في [BUILD_STATUS.md](BUILD_STATUS.md).

يوجد فحص قراءة فقط لا ينشئ حسابات:

```powershell
& 'C:\src\flutter\bin\cache\dart-sdk\bin\dart.exe' run scripts/check_backend.dart config/local.json
```

واختبار حي بملفي بريد جديدين يملكهما المالك في `scripts/live_smoke.dart`. يولّد كلمات مرور في الذاكرة ويختبر Auth والملفات والمطابقة والرسائل وRealtime والحظر والإبلاغ والصلاحيات. يحذف فقط حسابات الاختبار التي أنشأها بنفسه، ولا يغيّر حسابًا موجودًا. الخيار `--browser-url=https://mohamedmohsenarabtec-bot.github.io/NOVA/` يضيف تسجيل الدخول الحقيقي في Chrome وإعادة تحميل المحادثة، دون وضع كلمات المرور في ملف بناء أو URL أو سجل. نُفّذ هذا المسار ونجح، مع مراجعة صور قبل التحميل وبعده محليًا. الاختبارات العادية لا تُعتبر بديلًا تلقائيًا عن فحص المتصفح.

للاستخدام الآن افتح رابط التطبيق واختر «حساب جديد» بكلمة مرور تختارها من 12 حرفًا على الأقل. لا يلزم تأكيد بريد في بيئة التجربة الحالية. حسابا nova1 وnova2 كانا مؤقتين للاختبار وليسا حسابين مشتركين للاستخدام. قد يبقى الاكتشاف فارغًا حتى ينضم أشخاص متوافقون؛ لا نعرض أشخاصًا وهميين. تفعيل دور المالك في لوحة الإشراف يحتاج تسجيل حسابه أولًا ثم تعيين دوره من الخادم حسب docs/moderation.md.

## ما يعمل في الكود وما لم يكتمل

منفّذ: RTL/LTR، مظهران متجاوبان، Auth حقيقي، إعداد ملف تدريجي، تفضيلات العمر والنية والاهتمامات، اكتشاف خادمي، إعجاب وتخطّي ومطابقة، دردشة نصية، حظر وإبلاغ ودعم وحذف وتصدير جزئي، وبوابة إشراف محدودة على `/#/admin`. تشغيل هذه المسارات فعليًا يعتمد على تطبيق المخطط والتحقق منه.

غير مكتمل: الصور والصوت والتوثيق وFCM والدفع والاشتراكات الفعلية وMoments وOAuth/OTP ولوحة الإدارة الكاملة. جلسات الهاتف تستخدم التخزين الافتراضي للحزمة وتحتاج Keychain/Keystore قبل الإنتاج. المحادثات ليست مشفرة من طرف إلى طرف.

## الملفات الرئيسية

`lib/app` للجلسة والتوجيه، `lib/core` للإعداد والترجمة، `lib/features` للواجهات، `lib/shared/repository.dart` لاتصال Supabase، `supabase` للمخطط والأمان، `scripts` للتشغيل والفحص، `test` لاختبارات Flutter، و`docs` للتشغيل والأمن ومسودات الوثائق القانونية.
