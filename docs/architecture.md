# Architecture — NOVA 0.3

One Flutter 3.47.7 / Dart 3.13.5 application targets web, Android and iOS. The existing logo, local Arabic font, NovaTheme ThemeData and persisted NovaPreferences remain shared. StatefulWidget owns presentation state; NovaRepository is the Supabase boundary. Feature DTOs remain JSON maps; migration to generated typed models is a later maintainability improvement.

NovaBootstrap renders immediately, then loads preferences and initializes Supabase with deadlines and a retry state. It probes client_capabilities >=10; legacy client_readiness remains 4 for installed versions. NovaApp owns hash routes, locale/direction, light/dark/system themes and session gating. AccountScope supplies the authenticated repository to the shared notification bell. Ordinary account settings are accessible before optional onboarding is complete; dating discovery requires basic adult onboarding.

Profiles have a private own-row source and explicit server public projection. Optional fields are individually opt-in. Discovery returns only eligible projections, with reciprocal preferences, age, activity, report/block, test isolation and saved filters enforced server-side. Broad manual region is supported; precise location is not collected. Pagination is bounded offset; very large datasets will need stable keyset cursors.

PhotoEditor decodes/re-encodes JPEG/PNG/WebP locally, strips metadata, resizes and previews before upload. Server prepare creates owned pending metadata and an unguessable path; private Storage checks ownership, MIME/size and pending metadata. Finalization requires a real stored object. Photo metadata RLS handles public/matched/private visibility. The profile-photo Edge function authenticates each caller, reads metadata under caller RLS, and only then uses its server environment credential to stream bytes with no-store. Cross-user direct Storage reads are denied to avoid previously-authorized object-cache reuse after blocking. Native clients receive bytes, not shareable URLs. Content moderation/scanning is not implemented.

Discovery actions are unique per actor/target. A pair advisory lock and profile row lock serialize reciprocal matching and daily allowances. Pending likes expire after server-configured 48 hours by default; established matches/conversations are preserved. Pass dismisses a pending incoming interaction. Unmatch changes match state and denies further conversation access without deleting stored messages. Chat uses persistent RPC writes and authenticated Realtime invalidation with ready/reconnect catch-up and stale-result guards; opening the chat acknowledges unread state. Media/voice/reactions remain unimplemented.

Favorites are private own-row bookmarks with no target notification. Notifications contain event categories/references, never message bodies; unique event keys prevent duplicates. The shared bell polls unread state, and the inbox supports paging/read/all. Push is separate and absent. Retention is 90 days in the inbox; physical maintenance requires a scheduled authorized operator, not yet installed.

Membership offers are centralized server rows for Free/Plus/Premium and 1/3/6/12-month periods. Prices/currency are illustrative. Server entitlements gate advanced filters, daily allowances and liker identities. Purchase/restore interfaces remain disabled until receipt verification and store integrations exist. Proposed trials are server-only, identity-history guarded and OFF. No client button grants entitlements.

Referrals issue random codes, server-validated claims and aggregate progress without invitee identities. Approved rewards require manual qualification, account age, an external mutual match, server idempotency and an inviter-scoped lock enforcing rolling reward caps. Rules and daily product allowances come from server configuration. Rewards default OFF. A private HMAC identity history prevents immediate deletion/recreation benefit reuse for 180 days; this is not a complete device/fraud detection system.

Seven-day deletion requests hide the profile and can be cancelled during the grace period. Final purge/anonymization and scheduled retention workers are incomplete. Legacy direct account deletion still cascades through conversation data, so operators must review retention/legal requirements before a commercial launch. Own-data export remains private; staff navigation is role-aware and every staff operation is backend-authorized.

SharedPreferences stores app preferences and the Supabase default session persistence. Native encrypted-vault replacement is outstanding. Web sessions require HTTPS and origin security. No privileged credential exists in the Flutter config. iOS permission changes are shared-code preparation, not proof of an Xcode/device build.
